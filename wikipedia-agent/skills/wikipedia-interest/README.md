# wikipedia-interest — Agent Skill

Навичка у форматі [Agent Skills](https://agentskills.io/specification) для аналізу інтересу до тем за переглядами Wikipedia. Агент отримує відповідь на запитання «чи зростає інтерес до X мовами Y і наскільки цьому можна довіряти», а також графік і односторінковий PDF.

Інструкції для агента — у [SKILL.md](SKILL.md). Цей файл для людей.

## Структура

| Шлях | Що містить |
|---|---|
| `SKILL.md` | Інструкції для агента: одна команда, правила інтерпретації, формат відповіді |
| `scripts/wiki-interest` | CLI (запускається без встановлення пакета) |
| `scripts/wiki_interest/` | Код: `wikimedia.py` (API + кеш SQLite), `resolve.py` (відповідники статей через Wikidata), `stats.py`, `analysis.py`, `charts.py`, `report.py`, `cli.py` |
| `references/methodology.md` | Визначення метрик, оцінки довіри й обмеження |
| `assets/fonts/` | DejaVu Sans для кирилиці в PDF |
| `tests/` | Офлайн-тести (без мережі) |
| `evals/evals.json` | Сценарії для перевірки агента на моделях |

## Запуск

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt pytest
python -m pytest -q tests
python scripts/wiki-interest analyze --topic "Astronomy" --languages uk,pl,cs,de --period 2y
```

Змінні середовища: `WIKI_INTEREST_OUTPUT` (куди писати звіти, за замовчуванням `./output`), `WIKI_INTEREST_CACHE` (кеш), `WIKI_USER_AGENT` (Wikimedia вимагає ідентифікований User-Agent).

## Ключові рішення

| Рішення | Чому |
|---|---|
| Одна команда `analyze` робить усе (дані → метрики → графік → PDF) і повертає компактний JSON | Дешевій моделі потрібен 1 виклик інструменту і близько 4 тис. токенів на запит, а не написання коду |
| Відповідники статей через Wikidata, а не пошуком | Пошук «Intermittent fasting» у pl-Wikipedia повертає «Stres oksydacyjny». Відсутня стаття має бути позначена як відсутня, а не підмінена |
| Метрика з поправкою на розділ (`share_growth_pct`) | Загальний трафік розділів Wikipedia падає; без поправки будь-яка тема виглядає «спадною» |
| Сезонний тест Манна-Кендалла + «X/12 місяців вище, ніж рік тому» | Навчальні теми мають вересневі піки, а просте «останні 6 проти перших 6» їх плутає з трендом |
| Оцінка довіри з поясненням причин | Модель цитує причини, а не вигадує їх; правила детерміновані й покриті тестами |
| Тільки повні місяці, запит до останнього дня місяця | Див. помилку №2 нижче |
| Кеш SQLite: місяці незмінні, тож кешуються назавжди | Повторні й пов'язані запити обслуговуються без нових запитів до API |
| Команди `runs` / `show` / `report` | Повторні запити без повторного завантаження; PDF з висновками агента |

## Як я перевіряв результат AI-інструментів

Код писався за допомогою Claude Code. Кожен крок перевірявся на реальних даних і незалежним розрахунком, а не лише тестами, які написала та сама модель. Знайдені й виправлені помилки:

1. **Хибна стаття.** Перша версія (з AI-чернетки) шукала англійську назву в кожному мовному розділі. Для pl це давало «Stres oksydacyjny». Тепер використовуються відповідники через Wikidata, а тест `test_missing_language_never_falls_back_to_search_hit` фіксує поведінку.
2. **Один день замість місяця.** Графік показував падіння до нуля в останньому місяці для всіх мов. Ручний запит до API показав: per-article-ендпоінт обрізає місячний інтервал за днем кінцевої дати, тож `end=2026080100` дає лише 1 серпня (87 переглядів замість ~2900). Виправлено, тест `test_monthly_request_uses_last_day_of_end_month`.
3. **Неповний поточний місяць** потрапляв у тренд (вересень із 30 переглядами). Тепер дані обрізаються до останнього повного місяця, про що видається попередження.
4. **Надмірна довіра.** «High» при 231 перегляді на місяць, а також при протилежних знаках сирого й скоригованого тренду. Додано обмеження оцінки й тести.
5. **Кирилиця в PDF** відображалася квадратами (Helvetica). Додано шрифт DejaVu.
6. **Незалежна звірка цифр:** −59,6% для «Астрономія» (uk) перераховано напряму з API окремим скриптом; результат збігся до десятих.
7. **Візуальна перевірка:** кожну версію PDF і графіка рендерив у PNG і переглядав.

## Перевірка на дешевих моделях

`python -m app.evals --model <model>` у `wikipedia-agent/`: 5 сценаріїв із завдання, включно з повторним запитом і зміною припущень. Перевірки детерміновані (аргументи інструментів + текст відповіді).

| Модель | Пройдено | Викликів / запит | Токенів / запит |
|---|---|---|---|
| gpt-4.1-mini | 5/5 | 1–3 | 4–13 тис. |
| gpt-4o-mini | 4/5 | 1 | 4–8 тис. |
| gpt-4.1-nano | 4/5 | 1 | 4–8 тис. |

Провал на nano і 4o-mini однаковий: для запиту «підготуй звіт» вони не перегенеровують PDF власним текстом. Звіт усе одно створюється з автоматичними висновками й наступними кроками.

Що змінилося після першого прогону (nano 2/4). Інструмент приймає рядок команди, скопійований із SKILL.md, замість масиву аргументів: nano склеювала `"--topic \"X\""` в один елемент. Також вимкнено паралельні виклики (вони давали дублікати), додано псевдоніми кодів мов (`vn` → `vi`), а в результат `analyze` — підказку `next_action`.

## Як розвивати далі

Порядок визначається тим, що найбільше обмежує якість висновків зараз.

| Етап | Що | Навіщо / сигнал, що час |
|---|---|---|
| **1. Точність охоплення** | Додавати перегляди редиректів; автоматично підбирати пов'язані статті (категорії, «Див. також», Wikidata «part of») у кластер | Зараз враховується лише точна назва, і частина інтересу втрачається |
| **2. Надійність тренду** | Бутстреп-інтервали для зростання; STL-декомпозиція; детекція точок зламу (коли почалося зростання); перевірка на вбудованих сторінках-приманках | Користувачі питають «з якого моменту» і «наскільки впевнено» |
| **3. Більші обсяги** | Денна гранулярність за запитом; паралельні запити з обмеженням частоти; Parquet + DuckDB замість SQLite; масові прогони «50 тем × 20 мов» за маніфестом | Запити на рівні портфеля тем, а не однієї теми |
| **4. Масові дампи** | Для тисяч статей — місячні дампи pageviews (dumps.wikimedia.org) замість REST API, інкрементальне оновлення | Ліміти API (~100 запитів/с) стають вузьким місцем |
| **5. Контекст ринку** | Співставлення з розміром аудиторії мови, Google Trends, даними магазинів застосунків; мапінг мова → країни | Перехід від «інтересу» до «пріоритету ринку» |
| **6. Якість агента** | Більше сценаріїв оцінювання з LLM-оцінювачем у Phoenix; регресійний прогін на кожен PR; вимірювання вартості на запит | Кожна зміна SKILL.md має бути перевірена на дешевій моделі |
